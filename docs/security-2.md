# Проверка безопасности, проход 2 (версия 0.13.1)

Ноябрь 2026. Проверено всё, что появилось после первого прохода, — с этих версий данные уходят с устройств:

- облако: шифрование файлов, ключ облака, WebDAV, хранение пароля приложения;
- ИИ: ключ API, что уходит в Anthropic, «Спросить Claude» и записи Claude, внедрение команд через документы и данные;
- коннектор для приложения Claude: связь посредника `karman --mcp` с «Карманом»;
- новые команды ядра при блокировке, отладочные переключатели, права страницы и защита страницы (CSP);
- сторонние библиотеки.

Серьёзность — как в первом проходе: **средняя** — можно получить или испортить данные при не самых редких
условиях; **низкая** — нужны редкие условия или вред небольшой; **к сведению** — не ошибка, но стоит знать.
Высокой и средней серьёзности не нашлось.

## Что найдено и исправлено

### 1. Посредник коннектора отдавал ключ связи — низкая

Приложение Claude запускает `karman --mcp`, а тот передаёт запросы запущенному «Карману» на 127.0.0.1.
Порт и ключ связи «Карман» записывает в файл `claude.json` в своей папке данных; читать её может только ваша
учётная запись. Но когда «Карман» закрыт, в файле остаётся старый порт. Его может занять другая программа —
например, под другой учётной записью на том же компьютере. Посредник подключался к ней и сразу отправлял
ключ и запрос Claude (например, какую операцию записать), а в ответ мог получить что угодно — и Claude поверил бы.

**Теперь** ключ по сети не ходит:

1. посредник присылает одноразовое случайное число;
2. «Карман» отвечает доказательством, что знает ключ (MAC от этого числа), и своим числом;
3. только после этого посредник отправляет запрос — со своим доказательством.

Программа, занявшая порт, получает лишь случайное число: ни ключа, ни запроса. Посредник считает, что «Карман»
не запущен, и открывает его (на Windows). Если приложение Claude было открыто, пока «Карман» обновлялся,
старый посредник получит ответ «перезапустите приложение Claude».

### 2. Облако удаляло чужие файлы — низкая

Папка «Карман» лежит в корне Диска. При подключении облака заново (когда ключа облака нет) и при «Удалить данные
«Кармана» из облака» удалялись все файлы в подпапках `e` и `b` — даже те, что положили туда вы.

**Теперь** удаляются только файлы «Кармана»: `karman.key`, записи `…-с-по.kev` с правильными именами
и снимки `<32 знака>.kbl`. Пустые папки «Кармана» убираются, папки с вашими файлами остаются.

### 3. Простой пароль копий — низкая

С 0.13.0 пароль копий шифрует ещё и ключ облака, а файл ключа лежит на Диске: скачать его может любой, кто войдёт
в ваш аккаунт Яндекса или получит пароль приложения. Дальше пароль подбирают у себя, без ограничений по попыткам.
Argon2id с 64 МБ памяти сильно замедляет перебор, но пароли вроде «12345678» проверяются первыми.

**Теперь** новый пароль (пароль копий и пароль нового облака) не принимается, если он:

- из одних цифр короче 12 знаков;
- из трёх и меньше разных символов или повтор нескольких символов («abcabcabc»);
- ряд клавиш или символов подряд — «12345678», «qwertyui», «йцукенгш», «abcdefgh»;
- одно из самых частых слов-паролей с цифрами или без — «Пароль2026», «password123», «карман12».

Уже заданные пароли продолжают работать, пароль облака, которое уже есть, вводится как раньше. Лучше всего —
фраза из нескольких слов: «отпуск в Сочи 2026».

### 4. Смена пароля копий не меняет ключ облака — к сведению

Смена пароля копий перешифровывает тот же ключ облака: подключённые устройства продолжают обмен без нового
пароля. Но если старый пароль узнал кто-то, кто уже скачал старый файл ключа и видит Диск, он сможет читать
и новые файлы.

**Что делать в этом случае:** после смены пароля отключить облако с галочкой «Удалить данные «Кармана» из облака»
и подключить снова — появится новый ключ облака, другие устройства введут новый пароль. Подсказка — в окне смены
пароля копий и в [docs/cloud.md](cloud.md).

### 5. Удаление записей в «Спросить Claude» — к сведению

С разрешённой записью Claude в чате «Кармана» записывал, правил и удалял сразу, с кнопкой «Вернуть» после.
Внедрить команду через данные сейчас почти неоткуда: в «Карман» пишете только вы, документы Claude читает только
по кнопке, а их результат вы проверяете до записи. Но ошибиться Claude может и сам — понять «удали такси» шире,
чем вы имели в виду.

**Теперь** (как вы выбрали):

- удалить операцию или очистить рабочий день Claude только предлагает: под ответом — что именно и кнопки
  «Удалить» («Очистить») и «Оставить»;
- без кнопки ничего не удаляется; о решении Claude узнаёт вместе со следующим вопросом;
- записать и поправить — сразу, каждое действие с «Вернуть», как было.

В приложении Claude через коннектор — как было: запись только при «Разрешить запись», каждое действие с «Вернуть».

### 6. Пароль приложения Яндекса открывает весь Диск — к сведению

«Карман» работает только в папке «Карман», но пароль приложения даёт доступ ко всему Диску. Пароль хранится только
на устройстве: в зашифрованной базе и под защитой системы (DPAPI, Android Keystore). Программа, которая уже работает
под вашей учётной записью Windows, сможет его достать — как и ключ базы.

**Оставлено** (как вы выбрали). Создайте для «Кармана» отдельный пароль приложения с названием «Карман»: его можно
удалить в Яндекс ID, не трогая остальные. Доступ только к одной папке дал бы вход по коду через регистрацию «Кармана»
у Яндекса (код для него готов) — к этому можно вернуться позже.

### 7. Ключ базы и PIN-код — к сведению

Вопрос из первого прохода: привязать ли ключ базы к Windows Hello и отпечатку. С облаком цена выросла — пока «Карман»
заблокирован, не было бы и обмена через облако. **Оставлено как есть** (как вы выбрали).

### 8. Сторонние библиотеки — к сведению

- Rust, `cargo audit` по 527 библиотекам: уязвимостей нет. Предупреждения — те же пять, что в первом проходе,
  все только в сборке для Linux.
- Интерфейс, `npm audit`: уязвимостей нет. Новых пакетов интерфейса после первого прохода не добавилось.
- Новая библиотека приложения — `tauri-plugin-opener` (открыть страницу Яндекс ID в браузере). Странице она
  недоступна: её вызывает только ядро и только для адресов Яндекса и Google.

## Проверено, замечаний нет

- **Шифрование облака:**
  - ключ облака — 256 бит, на Диске — только под паролем копий (Argon2id); параметры Argon2id в чужом файле
    ограничены;
  - у шифрования файлов и имён снимков — свои ключи;
  - в проверку подлинности входят вид файла, номер облака и имя файла: подменённый, переименованный или чужой файл
    не расшифруется;
  - внутри файла записей проверяются автор и номера, у снимка — отпечаток содержимого;
  - пределы размеров при скачивании и распаковке;
  - откат и удаление файлов на Диске не портят записи: устройства видят пропуски и досылают своё.
- **WebDAV:**
  - только https, пароль — в заголовке входа по шифрованному соединению;
  - при переадресации вход не передаётся;
  - ответ сервера разбирается без внешних сущностей XML, размер ограничен;
  - имена файлов с сервера кодируются в адресе и не попадают в пути на устройстве.
- **ИИ:**
  - ключ API — только на устройстве, под защитой системы, Claude его не видит;
  - в Anthropic уходит только нужное для действия и только по вашей кнопке;
  - ответы Claude выводятся как текст, не как страница;
  - на вопрос — не больше 8 шагов с инструментами.
- **Блокировка:** все новые команды (облако, ИИ, «Спросить Claude», подтверждение удаления) отвечают «заблокировано».
  Обмен через облако в фоне продолжается — экран данных не показывает.
- **Отладочные переключатели** (адрес Claude API, имитация облака, короткие паузы) есть только в отладочной сборке.
- **Права страницы и CSP** не менялись: только события от ядра, внешних адресов у страницы нет.
