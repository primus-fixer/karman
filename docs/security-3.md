# Проверка безопасности, проход 3: связь по Wi-Fi (версия 0.15.0)

Ноябрь 2026. Проверено всё, что появилось в 0.15.0: поиск устройств в сети, связь по коду, ключ пары и обмен
со связанными устройствами в фоне. Как этим пользоваться — [docs/wifi.md](wifi.md).

Серьёзность — как в прошлых проходах: **средняя** — можно получить или испортить данные при не самых редких
условиях; **низкая** — нужны редкие условия или вред небольшой; **к сведению** — не ошибка, но стоит знать.
Высокой и средней серьёзности не нашлось.

## Как устроено

**Связь по коду.** Устройство показывает код из восьми знаков (40 бит). Второе вводит код, и оба выполняют
SPAKE2 — обмен ключами по паролю: сам код по сети не идёт, а из записанного обмена его не подобрать. Проверить
вариант кода можно только подключением к устройству с кодом; каждое подключение — попытка, их пять, код действует
пять минут и срабатывает один раз. После SPAKE2 подключившийся первым доказывает, что знает ключ, затем устройство
с кодом — и только потом идут записи.

**Ключ пары.** Из ключа SPAKE2 оба выводят ключ пары и запоминают его с номером другого устройства. Обмен со
связанным устройством: обе стороны присылают по 16 случайных байт, из них и ключа пары выводятся два ключа сеанса —
на каждое направление. Пакеты — XChaCha20-Poly1305, nonce — номер пакета.

**Поиск в сети.** Широковещательный запрос UDP. Отвечает устройство с показанным кодом (имя и порт — для списка
«Рядом в сети») и связанное устройство — его запрос подписан ключом пары, и ответ подписан тоже.

## Что найдено и исправлено

### 1. Поток подписанных запросов поиска — низкая

Чтобы проверить подписанный запрос от связанного устройства, «Карман» достаёт ключ пары из базы и из хранилища
системы (DPAPI, Android Keystore). Номер связанного устройства виден в его запросах, поэтому чужой в сети мог слать
тысячи поддельных запросов от его имени — «Карман» проверял бы каждый, нагружая базу; экран мог подтормаживать.

**Теперь** разбирается не больше 60 запросов поиска в секунду, остальные отбрасываются, не глядя. Связанным
устройствам хватает одного-двух запросов в минуту.

### 2. Подставной сервер и большой пакет — низкая

Пакет начинается с длины. Получатель сразу выделял память на всю объявленную длину — до 64 МБ — и только потом
читал данные. Устройство, занявшее прежний адрес связанного (например, после смены адресов в сети), могло ответить
на обмен и объявить пакет в 64 МБ — память выделилась бы одним словом, хотя данные не расшифровались бы.

**Теперь** память растёт по мере прихода данных; обрыв — ошибка, а не 64 МБ. До проверки ключа открытые сообщения —
не больше 4 КБ, первый шифрованный пакет к серверу — не больше 1 МБ.

## К сведению

### 3. Сорвать связь можно, связаться без кода — нет

Кто в той же сети, может пять раз подключиться с неверным кодом, пока он показан, — код отменится, и его придётся
показать заново. Можно занять приём подключений: одновременно — не больше четырёх, на открытое сообщение — 10 секунд,
так что обмен лишь откладывается. Получить записи или связаться так нельзя.

### 4. Имя устройства видно, пока показан код

Пять минут, пока показан код, на поиск отвечают всем: имя устройства и порт — чтобы выбрать устройство в списке
«Рядом в сети». Без кода чужим «Карман» не отвечает вовсе. Связанным отвечает только номер и порт — без имени.
Записанный чужим запрос связанного устройства можно повторить и получить такой же ответ: видно, что по этому адресу
есть «Карман», и только.

### 5. Код и QR-код

Как и QR-код с ключом до 0.15: кто увидел код или сфотографировал QR-код за эти пять минут, может связать своё
устройство и получить записи. На экране — предупреждение; код срабатывает один раз, отменяется кнопкой и блокировкой
«Кармана». Связанные устройства видны в списке — лишнее можно отвязать.

### 6. Связанное устройство получает всё

Связывают свои устройства, поэтому связанное получает все записи и снимки чеков — и в фоне, пока «Карман» открыт
(на компьютере — и в трее, и при блокировке PIN-кодом, как облако). Если телефон потерян, нажмите «Отвязать» на
компьютере: ключ пары удалится, и телефон больше не обменяется — «… не узнало это устройство». Порт обмена открыт,
только пока есть связанные устройства или показан код; отвязали последнее — порт закрыт совсем.

### 7. QR-код прежней версии

Телефон с 0.15 читает QR-код из 0.14 и старше: в нём одноразовый ключ, обмен проходит один раз по прежнему
протоколу, устройства друг друга не запоминают. Сам «Карман» 0.15 такой QR-код не показывает и прежний приём
подключений не открывает.

### 8. Сторонние библиотеки

- Новая библиотека — `spake2` 0.4.0 (RustCrypto) с `curve25519-dalek` 4.1.3 — в этой версии исправлена уязвимость
  по времени RUSTSEC-2024-0344.
- `cargo audit` по 533 библиотекам: уязвимостей нет. Предупреждений пять, все только в сборке для Linux: `glib`,
  `proc-macro-error` и с октября 2026 — `zbus_names`, `zvariant`, `zvariant_derive` (без поддержки). В сборки
  для Windows и Android они не входят.
- Интерфейс: новых пакетов нет.

## Проверено, замечаний нет

- **Код:** 40 бит, знаки равновероятны; пять минут, один раз; попытка засчитывается до проверки, одновременные
  попытки — под замком, больше пяти не выйдет. После пятой неверной — код отменён, верный тоже не проходит (тест).
- **SPAKE2:** группа Ed25519, разные роли сторон («karman-joiner», «karman-host») — сообщение не отразить обратно;
  подставное устройство, не знающее кода, получает «Код не подошёл» и ничего больше, а у вводящего код — ничего не
  уходит до подтверждения ключа (тест).
- **Подтверждение ключа:** сначала подключившийся, потом устройство с кодом; сравнение без утечки по времени.
- **Ключи:** ключ пары и ключи сеанса выводятся BLAKE2b с ключом, у каждого свой смысл в метке, части — с длиной.
- **Сеанс:** у каждого подключения свои случайные числа обеих сторон, ключи на каждое направление, номер пакета —
  в nonce. Переставленный и повторённый пакет не расшифровываются (тест). Повторить записанный обмен нельзя:
  ответная сторона пришлёт новые случайные числа.
- **Кто есть кто:** сервер сверяет, что приветствие от того устройства, чьим ключом подписан обмен; подключившийся —
  что ответило то устройство, до того как принять его записи. Чужой ключ — ни одной записи (тест).
- **Поиск:** чужому без кода — тишина; подпись чужим ключом — тишина; поддельный ответ без ключа пары не принимается
  (тесты).
- **Хранение:** связанные устройства и ключи пары — только на устройстве, в зашифрованной базе; ключи ещё и под
  защитой системы. В обмен, облако и резервные копии не попадают.
- **Блокировка:** все команды связи отвечают «заблокировано»; блокировка отменяет показанный код.
- **Адреса:** адрес, введённый руками, и адреса в QR-коде — только домашней сети.
- **Имена с другой стороны:** без управляющих знаков, до 64 знаков, на экране — как текст.
- **Отладочные переключатели** (второй адрес для поиска, короткие паузы, порт поиска) есть только в отладочной сборке.
- **Сквозные проверки** в настоящем приложении со вторым устройством: связь по коду, пять неверных попыток, обмен
  по ключу пары, автообмен, «Обменяться», «Отвязать» (порт закрыт, отвязанное устройство не узнаётся), связь
  с устройством из «Рядом в сети».

## Что проверить на устройствах

| Что | Как | Что должно получиться |
|---|---|---|
| Неверный код | На телефоне пять раз ввести неверный код | «Осталось попыток: 4… 1», затем «Код отменён» на обоих |
| Блокировка | Показать код, «Заблокировать сейчас», войти | Кода нет |
| Чужая сеть | В гостинице открыть «Карман» с другого устройства, не связанного | Компьютера нет в «Рядом в сети», пока на нём не показан код |
| Отвязать | Отвязать телефон на компьютере, на телефоне «Обменяться» | «… не узнало это устройство» |
| Брандмауэр | Первый «Показать код» на компьютере | Windows спрашивает про доступ к сети — разрешить для частных сетей |
